## 1. Resumo executivo

A P12.5 conecta a arquitetura P11/P12 ao produto real: **Demo anônimo isolado +
Playwright + E2E QA Agent + Evidence Pack + Triage + Controlled Fix Workflow**.
Antes de implementar, esta auditoria documenta o estado atual de cada superfície
relevante e o modelo de ameaças mínimo que a implementação deve respeitar.

**Autonomia máxima da P12.5: Level 3 (PR). Nunca Level 4 (auto-merge).**

## 3. Já existente que será reutilizado

- **Playwright**: `playwright.config.ts` + `tests/*.spec.ts` (auth, smoke, fluxo-completo, etc.) + scripts `test:e2e*`. A P12.5 cria o `BrowserAdapter` por cima (P12.5-05) sem acoplar o QA Agent ao Playwright direto.
- **Telemetry**: `src/ai/telemetry/` (envelope + completeness + persist) — P12.5 ADICIONA campos `browserSessionId/scenarioId/findingId/artifactId` e reusa a mesma infra (nunca telemetry paralela).
- **Workflow**: `src/components/workflow/WorkflowPipelineDag.tsx` + `pipeline-definition.ts` — o fluxo E2E (QA→Browser→Finding→Triage→Fix→Tests→E2E→Reviewer→PR) entra como pipeline observável.
- **KPI**: `src/components/kpi/` + `src/lib/aiEngineering.ts` — KPIs E2E entram como novas métricas.
- **Validation**: `src/ai/validation/` (P12) — runner determinístico reutilizado para simular runs E2E.
